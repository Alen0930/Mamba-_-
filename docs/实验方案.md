# 实验方案（AUC 主指标 + 多拓扑）

> 项目：Mamba 网络拆解　撰写日期：2026-09-11　版本：v1.0
> 适用阶段：消融 → GNN+BiMamba 重构 → 动态重算 → RL(PPO) 之后的「跨拓扑泛化 + 主指标对齐」阶段

---

## 一、研究假设

### 1.1 总假设

在**同条件对比**（统一的 AUC 口径、统一的序列补齐协议、各基线旋钮调到对它有利的位置）下，GNN+双向 Mamba 的逐节点策略能否在 BA/ER/WS 三类拓扑上稳定优于经典启发式与 CoreHD，并说明性能来自哪个组件。

### 1.2 子假设

| 编号 | 假设描述 | 验证方式 | 预期结果 |
|------|----------|----------|----------|
| H1 | 动态重算（每移除 b 节点在剩余子图上重算分数）的 AUC 显著低于静态一次性打分 | 组件消融 A1，三拓扑 × 30 图配对检验 | 动态 AUC 降低 ≥ 3%，p < 0.05 |
| H2 | 在 BA 上训练的模型迁移到 ER/WS 时 AUC 显著退化（跨拓扑泛化 gap） | 迁移实验 A3，BA-only 模型在三拓扑上评测 | ER/WS 的 rel_auc 劣于 BA |
| H3 | 混合拓扑训练（BA+ER+WS）显著缩小 H2 的泛化 gap | 迁移实验 A3，mixed 模型对照 | ER/WS 的 AUC 相对 BA-only 降低 ≥ 5% |
| H4 | RL(PPO) 微调在监督模型基础上进一步降低 AUC 与 stop_step | 主实验 M2 | AUC 降低且有统计显著性 |
| H5 | 训练/评测目标对齐（训练 `stop_condition` 由 1 改为 `0.01n`）改善 fc_value 且不损 AUC | 消融 A4 | fc 改善，AUC 不退化 |
| H6 | GCN 层数 2→3 主要利好近正则拓扑 WS，对 BA 影响小 | 超参分析 A2 | WS 的 AUC 改善幅度 > BA |
| H7 | **碎片化势函数的 reward 显著降低 fc_value，且不明显恶化 AUC** | 消融 A5（advantage 对照） | fc 显著下降；AUC 变化不显著或小幅上升 |
| H8 | **结构编码排序能让 Mamba 真正发挥作用**（优于 degree 序 / 优于纯 GCN） | 消融 A6 + A8 | 结构排序的 AUC 显著低于 degree 序 |

**H7 的动机（当前最大短板）**：主实验显示 AUC 已接近 CoreHD@0.01n（BA 0.1806 vs 0.1768，差 2%）而 **fc_value 差距大得多**（0.3445 vs 0.2984，差 15%）。说明策略能快速压低最大分量，但**打不散残留的中等分量**。

根因在 reward 设计：现有 per-step potential = `(LCC_before − LCC_after)/n0` **只看最大分量**。当图已碎成若干个 20 节点的分量（n0=500）时 LCC=20 恒定不变，reward 连续多步为 0——策略没有任何动力去拆它们，而 fc（LCC ≤ 1%）要求**所有**分量都小于 5。

**修正**：改用碎片化指数 P = `Σ(s_i/n0)²` 的下降量作为 per-step 信号。P 对**任何**分量的破裂都下降，且沿任意拆解序列单调不增（已单元验证：拆散一个 20-分量时 LCC 势下降 = 0，碎片势下降 = 0.0139）。

> **H1–H3 是本次的核心**：H1 回答「动态重算有没有用」，H2/H3 回答「跨拓扑泛化靠什么」。H4 是延续性验证，H5/H6 是工程性假设，用于定位收益来源。

### 2.2 依变量

| 变量名称 | 说明 | 量测方式 |
|----------|------|----------|
| **AUC（主）** | 鲁棒性曲线下面积 | `∫₀¹ S(q)dq`，`q=arange(1,n+1)/n`、`S=LCC/n`、`np.trapezoid`（`evaluate.calc_auc`） |

### 2.3 控制变量

| 变量名称 | 固定值 | 备注 |
|----------|--------|------|

| 监督标签 | CoreHD（seed=0） | 数据集生成时的标签 |
| 推理设备 | CPU | Mamba `use_fast_path=False` 下 CPU 快 ~1.5× |
| 硬件 | RTX 5060 Laptop 8.5GB | 训练用 CUDA |

## 三、评估指标

### 3.1 主要指标

| 指标名称 | 定义 | 选择理由 |
|----------|------|----------|
| AUC | 鲁棒性曲线下面积，越小越好 | 网络拆解领域公认的鲁棒性度量（Schneider 的 R），且**与 `stop_condition` 取值无关**（只要补齐协议统一），比"达到某阈值所需步数"更全面 |

### 3.2 辅助指标

| 指标名称 | 定义 | 选择理由 |
|----------|------|----------|
| stop_step | LCC ≤ 10% 的移除数 | 领域常用「瓦解速度」指标 |
| fc_value | LCC ≤ 1% 的移除占比 | 「彻底瓦解」指标；与 CoreHD 的 Sthreshold 直接对应 |
| rel_auc | 归一化 AUC | 跨拓扑可比（BA≈0.19 vs WS≈0.33，raw AUC 不可跨拓扑平均） |
| 耗时 | 单图推理秒数 | 说明精度-效率权衡（rl-greedy 是 b=1 逐步重算，比 b=25 贵 25×） |

### 3.3 统计方法

#### 3.3.1 分析单位与重复（先定义，再选检验）

本项目存在**两层嵌套**，必须分开对待：

| 层级 | 分析单位 | 数量 | 支撑什么结论 |
|------|----------|------|-------------|
| 外层 | **一次训练运行**（一个训练种子） | 1（当前）→ **≥3**（需补） | 「本方法能训练出优于基线的模型」 |
| 内层 | **一张测试图** | 见 §6.2 | 「这个已训好的模型在随机图上优于基线」 |

- 所有方法在同一批测试图上评测 → **配对设计**（paired），用配对检验。
- **红线**：30 张测试图 **不能**当成 30 个独立样本去支撑「训练方法有效」——它们是同一个固定模型在 30 个输入上的重复测量。**要支撑方法级结论必须多训练种子**（§6.4）。
- 报告时明确 `n` 指什么：写「n = 30 test graphs per topology, single training run」或「n = 3 training seeds, each evaluated on 30 graphs」。

#### 3.3.2 怎么读结果（实验过程中直接用的判定规则）

- **主检验**：**Wilcoxon signed-rank**（配对、非参数）。`scipy.stats.wilcoxon(a, b)`，a/b 是同一批图上两个方法的 AUC。
- ⚠️ **样本量硬约束**：n 个配对样本下最小双侧 p = 2/2ⁿ。**n=5 → 最小 p=0.0625 > 0.05，永远得不出显著结论**（已数值验证）。所以：

  | 配对样本数 | 最小可达 p | 说明 |
  |---|---|---|
  | ≤5 | ≥0.0625 | **不可用于检验**，跑了白跑 |
  | 6–7 | 0.031 / 0.016 | 勉强，只有完全一致的差值才能显著 |
  | 8–10 | 0.008 / 0.002 | 可用，功效约 0.47 / 0.63 |
  | ≥20 | <0.001 | 功效 >0.9 |

- **交互作用检验（针对 H6，容易读错）**：**「WS 上显著、BA 上不显著」不能推出「GCN 加层主要利好 WS」**——差异的显著性 ≠ 显著的差异。要下这个结论必须**直接检验交互**：对 `ΔAUC = AUC(3层) − AUC(2层)` 做 BA vs WS 的组间比较。
- **排除规则（事先定好，避免自我欺骗）**：测试图若 `n_actual < 0.98 × n_requested`（取 LCC 后丢节点 >2%，主要见于小规模 ER），**保留但记录**，另跑一遍剔除后的结论看是否变化。不做事后剔除。
- **不池化**：
  - 不跨拓扑平均（BA≈0.19 vs WS≈0.33，混平均被拓扑配比支配）→ 用 `rel_auc` 比较
  - 不跨规模池化（30/10/8 样本数不同，池化后被 n=500 支配）→ 分规模报告
- 软件：`scipy.stats.wilcoxon`（scipy 1.18.1，n≤25 走精确法）。够用了，效应量/多重校正等写论文时再补。

## 四、Baseline 设定

### 4.1 Baseline 列表

| 名称 | 类型 | 来源 | 备注 |
|------|------|------|------|
| random | 简单基线 | `dismantle(method='random')` | 拓扑无关锚点（AUC ≈ 0.44–0.46） |
| degree | 简单基线 | `dismantle(method='degree')` | 静态启发式，本领域默认下界 |
| pagerank | 经典方法 | `dismantle(method='pagerank')` | 静态谱方法 |
| **CoreHD@{1, 0.01n, 0.1n}** | 经典方法 / 动态上界 | `dismantle(method='CoreHD', stop_condition=…)` | **必须报三档 Pareto 前沿并标注 Sthreshold** |
| gnn-static | 本方法（静态） | `dismantle(method='mamba_gnn')` | 消融 H1 的对照 |
| gnn-dyn-b{10,25,50} | 本方法（动态） | `batch_size=b` | H1 的扫描 |
| rl-greedy | 本方法（RL） | `eval_rl.greedy_sequence` | 批粒度 b=1（与 CoreHD 同粒度） |

> **CoreHD 的 Sthreshold 是本项目踩过的最大坑**：此前一直用 `Sthreshold=1`（对它最不利的配置）作基线，导致得出「fc 超越 CoreHD 23%」的错误结论。对齐到 fc 目标（`Sthreshold=0.01n`）后 CoreHD 的 fc 从 0.3995 降到 0.2646（BA），三项指标全面变好。
> **同时注意 CoreHD 不可两全**：`Sthreshold=0.1n` 的 stop_step 最好但 fc 最差，`0.01n` 反之 → 必须报 Pareto 前沿。

### 4.2 公平比较设定

- **评估脚本**：`eval_multitopo.py`（唯一入口），`--device cpu`
- **序列协议**：所有方法经 `unified_interface.dismantle()` 返回**长度 n 的完整序列**；RL 的 `greedy_sequence` 用 `evaluate.complete_sequence` 补齐（此前它返回截断的 ~0.3n 序列，直接算 AUC 会虚低、与基线不可比）
- **随机性**：CoreHD/GND/EI/random 固定 seed=0；degree/pagerank 本身确定
- **批粒度标注**：表中必须标注 gnn-dyn 的 b 与 rl-greedy 的 b=1，不能把 b=25 与 b=1 并列成"同条件"
- **基线调参**：CoreHD 按 Sthreshold 扫描（见上），degree/pagerank 无超参

### 5.1 完整消融（组件）

| 变体 | GCN 编码 | 双向 Mamba | 动态重算 | RL 微调 | 预期效果 |
|------|---------|-----------|---------|--------|----------|
| degree | — | — | — | — | 最差（静态下界） |
| 纯 Mamba（静态） | ✗ | ✓ | ✗ | ✗ | 略优于 degree |
| GNN+Mamba（静态） | ✓ | ✓ | ✗ | ✗ | 静态天花板 ≈ degree |
| **GNN+Mamba（动态）** | ✓ | ✓ | ✓ | ✗ | 显著优于 degree（H1） |
| **+ RL 微调** | ✓ | ✓ | ✓ | ✓ | 最优（H4） |
| w/o GCN | ✗ | ✓ | ✓ | ✓ | 退化 → 证明邻接矩阵有效 |

### 5.2 超参敏感度分析

| 超参数 | 取值范围 | 取值点 | 分析目的 |
|--------|----------|--------|----------|
| 动态重算批粒度 b | 1 – 50 | 1, 5, 10, 25, 50, ∞(静态) | 精度-效率权衡，找最优区间（H1） |
| GCN 层数 | 2 – 4 | 2, 3, 4 | WS 上感受野是否够（H6） |
| RL action_k | 5 – 20 | 5, 10, 20 | 批动作粒度对训练/评测 mismatch 的影响 |
| 训练图规模 | 500 – 1500 | 固定 / 多规模 | 跨规模泛化 |
| RL advantage 形式 | 3 种 | potential / lcc / **frag** | 验证 H7（信号是否覆盖整个分量分布） |

**A5（advantage 对照，验证 H7）**——严格单变量：其余全部固定，只换 `--advantage`。

| 臂 | advantage | 势函数 | 监督初值 | 种子 | 状态 |
|---|---|---|---|---|---|
| a | `potential` | `LCC/n0`（只看最大分量） | `gnn_mamba_mixed` | 42 | ✅ 已完成（`gnn_mamba_rl_mixed`） |
| b | `frag` | `Σ(s_i/n0)²`（看整个分量分布） | `gnn_mamba_mixed` | 42 | 🔄 本轮 |
| c | `lcc` | `-LCC_after/n0` | — | — | 理论预警不佳，暂不跑 |

判据：在 n=500 × 30 图/拓扑上做配对 Wilcoxon（k=30）。**成功条件** = fc 显著下降（p<0.05）且 AUC 上升不显著（p>0.05）；**若 AUC 上升也显著**，则说明是权衡而非改进，需报告两个指标的 Δ。

### 5.5 序列模型消融（验证方法的核心主张）

方法的核心主张是「Mamba 沿有序序列捕捉**跨节点长程依赖与全局结构**」。用两个旋钮直接检验：

| 编号 | 变体 | 实现 | 检验什么 |
|---|---|---|---|
| A6 | 无序列模型 | `--n-mamba-layers 0`（纯 GCN，13K 参数） | Mamba 到底有没有贡献 |
| A7 | 序列模型类型 | `--seq-model {mamba,attention}` | 质量与效率对比 |
| A8 | 节点序列排序 | `--order {degree,bfs,dfs,core}` | **结构编码是否能喂给 Mamba** |

**关键设计推论（已实测确认）**：GCN 对节点置换等变 —— 纯 GCN 模型在三种排序下 AUC **完全相同（0.3063）**。因此**排序的全部效应都只通过 Mamba 起作用**，「无 Mamba + 任意排序」是同一个模型。于是：
- 若 A6 ≈ 完整模型 → Mamba 目前没做事
- 若 A8 中结构排序显著优于 degree 序 → 让 Mamba 做事的关键在「喂什么序列」

**填充污染的实测不对称**（同一张 45 节点图 pad 到不同长度，有效节点输出变化）：

| 序列模型 | \|L45−L60\| | \|L45−L90\| | 判定 |
|---|---|---|---|
| 双向 Mamba | 5.45e-03 | 5.45e-03 | **受污染** |
| 自注意力 | 1.19e-06 | 1.19e-06 | 不受影响 |
| 无序列模型 | 1.19e-06 | 4.77e-07 | 不受影响 |

SSM 没有掩码机制，padding 会进入序列并影响有效节点（相对分数尺度约 0.5%）。已用长度分桶把 padding 从 567 降到 38 来缓解。**做 Mamba vs 注意力对比时必须写明这一固有不对称**。

## 五之三、H7 结果：碎片化 reward **被否定**（做得更差，不是更好）

严格单变量（同监督初值 `gnn_mamba_mixed`、同种子 42、同超参，只换 `--advantage`），
n=500 × 30 图/拓扑，配对 Wilcoxon（k=30）：

| 拓扑 | 指标 | `potential`（原版） | `frag`（碎片化） | Δ | p | 判定 |
|---|---|---|---|---|---|---|
| BA | AUC | 0.1833 | 0.1894 | −0.0061 | <1e-5 | **frag 更差** |
| BA | fc | 0.3801 | 0.5355 | −0.1554 | <1e-5 | **frag 更差** |
| ER | AUC | 0.2963 | 0.2995 | −0.0032 | <1e-4 | **frag 更差** |
| ER | fc | 0.5186 | 0.6172 | −0.0986 | <1e-5 | **frag 更差** |
| WS | AUC | 0.3247 | 0.3266 | −0.0019 | 0.044 | **frag 更差** |
| WS | fc | 0.5941 | 0.6245 | −0.0304 | <1e-4 | **frag 更差** |

**三个拓扑 × 三个指标全部变差，无一例外。**

### 失败原因（这条比结果本身更重要）

我原来的推理是「LCC 信号在图碎成中等分量后归零，需要碎片化指数补梯度」。**方向对，但势函数选错了。**

fc 要求 **最大分量 ≤ 1%·n**。而碎片化指数 `P = Σ(s_i/n)²` 的最小值出现在**各分量大小相等**时 —— 例如碎成 20 个各占 5% 的分量：`P = 20×(0.05)² = 0.05`（很低），但 **LCC = 5% > 1%，fc 永远达不到，episode 跑满也不满足停止条件**。

也就是说：**碎片化目标奖励的配置，恰恰是 fc 最差的配置**。策略学会了把图切成许多大小相当的中等块（"看起来很碎"），却始终无法把最大分量压到 1% 以下。BA 上 fc 从 0.3801 恶化到 0.5355 正是这个机制的体现。

**结论：对 fc 而言，正确的势函数本来就是「最大分量」本身**——原版 `potential` 已经是对的。fc 落后 CoreHD 的原因**不在 reward 形状**，而在模型识别结构关键节点的能力。这把注意力正确地引向了序列排序实验（A8）。

### 5.7 H8 结果：结构编码排序**让 Mamba 开始做事**（2/3 拓扑上成立）

同一训练配置（`n_gnn_layers=3`、`n_mamba_layers=2`、AUC 选模型、长度分桶、seed 42），
只换数据集烘焙的节点序列排序；n=500 × 30 图/拓扑，配对 Wilcoxon（k=30）：

| 拓扑 | 指标 | dfs vs **degree 序** | dfs vs **纯 GCN** | dfs vs **CoreHD@0.01n** |
|---|---|---|---|---|
| BA | AUC | **−0.0021** (p=5.7e-4) ✓ | **−0.0028** (p=6e-5) ✓ | +0.0079 落后 |
| BA | fc / stop | 不显著 | 不显著 | 落后 |
| ER | AUC | −0.0009 (p=0.21) | **+0.0035** (p=7e-5) ✗ | +0.0058 落后 |
| ER | fc | 不显著 | +0.0100 (p=0.013) ✗ | 落后 |
| WS | AUC | **−0.0054** (p=9e-5) ✓ | **−0.0055** (p=7e-5) ✓ | **−0.0034** (p=0.011) ✓ **胜** |
| WS | fc | **−0.0163** (p=0.0014) ✓ | **−0.0267** (p=2e-5) ✓ | +0.0549 落后 |
| WS | stop | **−7.2** (p=0.0034) ✓ | −1.3 (p=0.67) | +6.83 落后 |

**四个结论：**

1. **dfs 序在 BA 与 WS 上同时显著优于 degree 序和纯 GCN。** 由于 GCN 对置换等变（纯 GCN 在三种排序下 AUC 完全相同），质量提升**只能来自 Mamba**——这是 Mamba 有贡献的**直接证据**。H8 在 2/3 拓扑上成立。

2. **WS 上首次显著战胜 CoreHD@0.01n**（0.3225 vs 0.3259，p=0.011）。

3. **收益只在动态重算下出现**：静态对比 dfs vs degree 是 Δ=−0.0001/p=0.75（BA）、−0.0012/p=0.080（WS），几乎无差别；**动态 b25 下才显著**（p=5.7e-4 / p=9e-5）。解释：移除节点后的**残留碎片结构**正是遍历序能编码的，而一次性静态打分不需要它。这与「动态重算是突破口」的主线一致。

4. **ER 是例外**：dfs 仍不如纯 GCN（+0.0035，显著）。ER 度分布均匀、无 hub，遍历序在残留碎片上可能引入噪声。**未解决，列为待查。**

### 5.7.1 四种排序完整对照（k=30 配对检验）

| 拓扑 | **dfs** | degree | core | 纯 GCN | dfs 的显著性 |
|---|---|---|---|---|---|
| BA | **0.1847** | 0.1867 | 0.1878 | 0.1874 | 显著优于**全部三个**（p=6e-5 / 5.7e-4 / 2e-5）|
| ER | 0.2992 | 0.3002 | 0.2984 | **0.2957** | 不如纯 GCN（+0.0035, p=7e-5）；与 degree/core 不显著 |
| WS | **0.3225** | 0.3279 | 0.3279 | 0.3280 | 显著优于**全部三个**（p=7e-5 / 9e-5 / 2e-5）|

**DFS 是赢家；`core` 排序（k-core 剥壳分层）完全无效**——三个拓扑上都与 degree 序无显著差异。原本预期 core number 是强先验（它是 GCN 的局部消息传递推不出的**全局量**），**这个预测被否定**。可能原因：core 序按层分组后，同层节点在序列中相邻但图上未必相关，反而打散了 GCN 需要的局部结构；且每步移除后 residual graph 的 core 结构剧变、排序不稳定。**待查。**

### 机制解释（为什么度排序下 Mamba 无事可做）

度排序下，**序列位置 ≈ 度排名，而度已经是模型的输入特征**——Mamba 的位置信息与输入特征**冗余**，因此它怎么算都不改变节点排序（训练后探针：只看 GCN 分支与完整模型的排序 ρ>0.99）。DFS 序下**位置编码的是「图上游走的位置」，这是 GCN 看不见的信息**，Mamba 的贡献才变得非冗余。这也解释了为什么「换排序」比「换 reward」有效。

### 5.8 扩展性对比（A7）—— 结论与方法论述不符，且原因是硬件

`bench_scaling.py`，相同 GCN/d_model/层数，前向+反向中位耗时：

| N | 双向 Mamba | 自注意力 | 比值 |
|---|---|---|---|
| 500 | 0.691 s | 0.008 s | 86× |
| 1000 | 1.760 s | 0.016 s | 110× |
| 2000 | 6.623 s | 0.050 s | 132× |
| 4000 | 50.590 s | 0.161 s | **314×** |

拟合增长指数：**Mamba k≈2.1、注意力 k≈1.4** —— 与「Mamba 线性 / 注意力二次」**相反**。

**根因是硬件而非算法**：`gnn_mamba_model.py` 在模块加载时强制把 `selective_scan_fn` 替换为 `selective_scan_ref`（纯 PyTorch 参考实现），因为预编译的 mamba_ssm CUDA kernel 不支持 RTX 5060 的 sm_120。**因此本机测得的 Mamba 耗时不代表其真实性能**，O(N) 的论断针对优化过的 kernel，在本机无法验证。

**硬件无关、仍然成立的部分是内存**：注意力的中间量是 B·heads·N²·4B，即 O(N²)（N=4000 时单层 256MB、N=8000 时 1GB、N=16000 时 4GB）；Mamba 的 SSM 状态是 (B, d_inner, d_state)，**与 N 无关**。这一条才是「天然适配大规模网络」的可靠论据。

> 引用该结论时必须标注测试硬件与 kernel 回退状态，否则会被误读为「Mamba 比注意力慢」。

### 6.2 评测预算重新分配（**关键修正**）

原计划「3 拓扑 × 3 规模 × 2 seed = 18 图」有两处问题：

1. 每格只有 2 个配对样本，**做不了显著性检验**；
2. 更硬的问题——**Wilcoxon 在 n 个配对样本下的最小双侧 p = 2/2ⁿ**。已数值验证：**n=5 时最小 p=0.0625，永远无法达到 p<0.05**（n=6 才刚好 0.03125，n=8 才有余量）。

评测成本随 n 急剧上升（n=1500 的 rl-greedy 是 n=500 的 3×），而**检验力取决于配对样本数、不取决于 n**。因此把预算集中在便宜的规模上换样本量：

| 规模 | 每拓扑图数 | 总图数 | 最小可达 p | rl-greedy 成本 | gnn-dyn-b25 成本 | 合计 |
|------|-----------|--------|-----------|---------------|-----------------|------|
| n=500 | **30** | 90 | <0.001（功效 0.99） | 90 × 37 s ≈ 56 min | 90 × 2 s ≈ 3 min | ~1.0 h |
| n=1000 | 10 | 30 | 0.002（功效 0.63） | 30 × 75 s ≈ 38 min | 30 × 6 s ≈ 3 min | ~0.7 h |
| n=1500 | **8**（原 5，**不可用于检验**） | 24 | 0.008（功效 ≈0.47） | 24 × 110 s ≈ 44 min | 24 × 15 s ≈ 6 min | ~0.9 h |
| **合计** | | **144** | | | | **~2.6 h** |

> 配对效应量假设：真实 AUC 差 0.005、配对标准差 0.006（同图比较，图间方差被配对消掉）。功效为 2000 次模拟结果，非形式化 power analysis。
> n=1000/1500 的功效偏低（0.47–0.63），这两个规模**只作趋势性报告**，主结论落在 n=500；若要在这两个规模下强结论，需把图数提到 ≥15 或降低效应量门槛。

对比原方案（18 图、~1.5 h、每格 2 样本、n=1500 无法检验）——成本相当，但核心对比的配对样本从 6 个提升到 **30 个**。

### 6.3 训练噪声地板（**该花的一次性开销**）

做实验时最容易骗自己的事：**改了一个东西，结果动了，就认定是这个改动起的作用**。但训练本身有随机性（初始化、数据顺序），单次运行之间的差异可能就有这么大。

低成本做法：**同一个配置跑 2 个种子**，量出「什么都不改时的 AUC 波动」作为噪声地板。之后所有对比都必须明显超过这个地板才算真信号。

| 检查项 | 成本 | 用途 |
|--------|------|------|
| 同配置 2 个训练种子（mixed, 3 层） | +2.3 h | 得到训练噪声地板 σ_train |
| 同配置 2 个 RL 种子 | +3.2 h | 得到 RL 阶段噪声地板 |

判据：若两次运行的 AUC 差 < 噪声地板，**不要**把它归因于所改的那个变量（改超参、换数据都一样）。

## 九、风险与应对

### 9.1 读结果时最容易犯的错（**实验过程中自查用**）

| 错法 | 为什么错 | 正确做法 |
|------|----------|----------|
| **把 30 张图当成 30 个独立样本** | 它们是同一固定模型在 30 个输入上的重复测量，只能说明「这个模型在随机图上如何」，不能说明「训练方法有效」 | 涉及训练配置的对比，必须看**训练噪声地板**（§6.3）；图数只解决评测噪声 |
| **改了 A，结果动了，就认定是 A 起作用** | 训练本身有随机性，单次差异可能全来自种子 | 先量噪声地板，改动效果必须明显超过它 |
| **「WS 上显著、BA 上不显著」→ 结论「加层主要利好 WS」** | 差异的显著性 ≠ 显著的差异 | 直接检验交互：对 `ΔAUC` 做 BA vs WS 组间比较 |
| **用 n≤5 的配对样本下显著性结论** | Wilcoxon 最小 p=2/2ⁿ，n=5 → 0.0625，数学上不可能显著 | 每格 ≥8 个配对样本（§6.2） |
| **跨拓扑或跨规模取平均** | 拓扑间 AUC 差近一倍、规模间样本数不同，平均值没有意义 | 分拓扑、分规模报告；跨拓扑用 `rel_auc` |
| **看到「不显著」就当成「没有差别」** | 功效不足时也会不显著（n=1500 功效仅 0.47） | 报功效或直接说明「该规模样本量不足以判定」 |
| **事后剔除「异常」图** | 事后剔除 = 挑选结果 | 排除规则事先定（§3.3.2），并做剔除敏感性分析 |

### 9.2 实验风险

| 风险 | 可能性 | 影响 | 应对方案 |
|------|--------|------|----------|
| **WS 学不动**（度分布 [3,10] 近正则 + CoreHD 标签在 WS 上只比 degree 好 17%） | 中 | 高（三拓扑结论不完整） | 已用 3 层 GCN；若仍退化，如实作为「困难拓扑」结论并分析失败模式 |
| **RL 微调后跨拓扑能力回退**（在混合分布上采样仍可能偏斜） | 中 | 中 | RL 用 `--graph-type mixed`，与监督训练分布一致；对比 RL 前后各拓扑 AUC |
| **fc_value 全面落后 CoreHD@0.01n** | 高 | 中 | 已确认该差距真实存在；不掩盖，转为「AUC/stop 领先、fc 落后」的诚实表述，并分析原因（reward 不直接惩罚"残留巨片"） |

## 十、备注

**本项目三次栽在同一类坑——「指标与优化目标错位」**，本方案的设计针对性地防这三类：

1. **loss / 拆解指标错位**（阶段 A-B）：ListMLE 验证损失更低但拆解更差 → 现已把选模型准则改为 AUC
2. **reward / 目标错位**（RL v2/v3）：critic 学不会 / 整条 return 太粗导致策略退化 → 已用 per-step potential advantage
3. **拿对手最不利的配置当基线**（刚发现）：CoreHD 用 `Sthreshold=1` 导致 fc 优势假象 → 现报三档 Pareto 前沿

**方法论要求**：凡是要下「超越某方法」的结论，先确认那个方法的旋钮有没有被调到对它有利的位置。
